# 行李物品标注与识别平台

独立于 `lora-webui`（教材 SD1.5 平台）的**单独项目**——只是界面风格参考它，业务完全独立。

> 如果你要找的是教材那个 SD1.5 的 LoRA 训练平台，它在
> `..\lora-platform\lora-webui`，跟这里没有任何关系。

## 启动

**推荐**：双击项目根（`luggage-agent\`）的 **`启动标注平台.bat`**，会自动开浏览器。

地址：**http://127.0.0.1:8004**

关掉那个黑色窗口 = 停服务 + 释放显存。

> 脚本会先检测 8004 是否已在运行：在运行就只开浏览器（**不会重复起服务**）；
> 没运行才启动。所以可以放心重复双击。

也可以双击本目录下的 `启动平台.bat`，效果一样。

命令行启动（在 `luggage-agent\` 下）：

```bat
D:\10604\ANACONDA\envs\lora\python.exe anno-tool\backend\app.py
```

> 地址栏看到的还是旧界面时，用 `Ctrl+Shift+R` 硬刷新（或打开 `http://127.0.0.1:8004/?t=2`）。
> 后端已禁用前端缓存，正常情况下刷新即可。

## 四个标签页

| 标签页 | 干什么 |
|---|---|
| **数据集（我的标注）** | 缩略图网格看全部图，角标显示每张图的框数；可切**场景**、**删图**；点图片直接跳去标注 |
| **方框标注** | 在图上画框 / 移动 / 缩放 / 改名 / 删除，AI 自动标注，LoRA 识别，保存，导出训练数据 |
| **VLM 识别** | **面向用户的测试页**：先选场景，再传照片，回答「带齐了没、东西在哪」，并给**只读方框预览** |
| **物品清单** | 32 项规范名 + 类别 + 别名表 + 归属场景，**可直接在平台上增删改** |

### 场景切换（旅行 / 上学）

平台支持两套场景，模型是同一个，靠「给哪份清单」区分：

- **旅行**：28 项，不含书本 / 文具等上学专属项
- **上学 / 回家**：31 项，不含门票 / 相机等旅行专属项

两处可以设场景：

1. **数据集页**每张图卡片上的单选（`旅行` / `上学`）→ 决定这张图导出训练时用哪份清单
2. **VLM 识别页**顶部的场景单选 → 决定这次识别的提问清单

> 清单项归属哪些场景，在「物品清单」页编辑；缺省 = 两场景通用。

### 画框怎么操作

| 动作 | 效果 |
|---|---|
| 在空白处拖拽 | 新画一个框 |
| 点框 | 选中（出现 8 个控制点） |
| 拖框内部 | 移动 |
| 拖角点 / 边点 | 缩放 |
| 右侧下拉 | 改物品名（按类别分组，含全部别名；**可直接输入新名字**） |
| 右侧「删除」 | 删掉这个框 |

> ⚠️ 画完记得点**保存标注**，不然白画。

**名字可以直接输入**：下拉里没有的名字也能敲进去（`allow-create`），右侧会实时提示
「建议写具体名 / 非本场景 / 无法归类」，保存时经 `normalize.py` 自动归到规范大类。

### AI 自动标注

点「AI 自动标注」会用 GroundingDINO 预标一版框（首次调用要加载检测模型），
你再手动改名字、删误检、补漏标。它会**替换当前图的所有框**，所以有未保存改动时先保存。

### 删图

数据集页每张图卡片的「删除」按钮 → 移到 `data/labeled/_trash/`（**不真删**，
可在资源管理器里找回），同时清掉它的标注与场景设置。

## 目录结构

```
luggage-agent\
  启动标注平台.bat      ★ 双击这个启动（会自动开浏览器）
  anno-tool\            ← 本平台（新版）
    backend\app.py      后端
    web\                前端（Vue3 + Element Plus，本地库，免构建、免联网）
      index.html
      app.js
      vendor\           vue.global.prod.js + element-plus
    启动平台.bat        备用启动（效果同上）
  _旧版备用_anno-tool\  ← 旧版标注平台（8003），已归档，仅作为依赖保留
```

**免构建**：前端直接改 `web/index.html` 或 `web/app.js`，刷新浏览器就生效，
不需要跑 `npm run build`。前端库是本地文件，断网也能用。

## 对外接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 资源状态 |
| GET | `/api/images` | 图片列表 + 全部标注 + 场景映射 |
| GET | `/api/image/{name}` | 取图 |
| **DELETE** | `/api/images/{name}` | **删图**（默认移入 `_trash/`，`?hard=true` 才真删） |
| GET | `/api/canon` | 规范名 + 类别 |
| GET | `/api/taxonomy` | 完整清单（含别名与场景） |
| **POST** | `/api/taxonomy/items` | **新增清单项** |
| **PUT** | `/api/taxonomy/items/{old_name}` | **改清单项**（改名时同步改已标注的框） |
| **DELETE** | `/api/taxonomy/items/{name}` | **删清单项** |
| **POST** | `/api/classify` | 判断一批名字会归到哪个规范名 |
| **GET** | `/api/scenarios` | 场景列表 + 各场景清单项 + 每图场景 |
| **PUT** | `/api/image-scenarios` | 设置每张图所属场景 |
| PUT | `/api/annotations` | 保存标注（**合并式**，只覆盖本次提交的图） |
| POST | `/api/upload` | 上传图片 |
| POST | `/api/autodetect/{name}` | GroundingDINO 预标 |
| POST | `/api/recognize/{name}?scenario=` | LoRA 语义识别（按场景提问） |
| POST | `/api/export` | 导出 train.jsonl（按图所属场景取清单与指令） |
| GET | `/api/stats` | 统计 |

> 清单增删改后会**热重载**：`normalize.py` 归类规则、GroundingDINO 提示词、
> 各场景指令一并刷新，不用重启服务。

## 数据落在哪

| 数据 | 路径 |

## 新旧版本的关系

本平台（新版）已占回 `anno-tool\` 这个位置；旧版归档为 `_旧版备用_anno-tool\`。

| | `_旧版备用_anno-tool`（旧） | `anno-tool`（本平台，新） |
|---|---|---|
| 界面 | 简易单页 | 多标签页（风格参考 lora-webui） |
| 数据集总览 | 无缩略图网格 | 有 |
| 物品清单 | 只能手改 json | **平台上可直接增删改** |
| 自由输入名字 | 会被吞掉 | 可自由输入，并实时提示能否归类 |
| 场景切换 | 无 | 旅行 / 上学，图与识别都可切 |
| 删图 | 无 | 有（移入 `_trash/` 可找回） |
| 识别预览 | 无 | VLM 识别页给只读方框预览 |
| 端口 | 8003 | **8004** |

两者的标注数据**是同一份**（都读写 `manual_annotations.json`），可以混用。

> ⚠️ `_旧版备用_anno-tool\` 先别删。新版后端的 AI 自动标注（GroundingDINO）
> 仍在复用它的代码。它必须保持为 `luggage-agent` 的**直接子目录**——
> 内部靠 `parent.parent` 反推项目根，再往下套一层目录就会失效。
